Chapter Three

Under what circumstances is privacy maintained?

4. Seeking a Robust Standard

After witnessing how easily simple statistics can lead to full data reconstruction, we must ask: Is there a way to guarantee privacy? Instead of just reacting to known attacks (like linkage or differencing attacks), we need a mathematical property that provably resists any possible attack—even those not yet invented.

4.1 The Intuition of Tore Dalenius (1977)

One of the earliest attempts to define privacy came from Tore Dalenius. He proposed a simple but powerful idea: Access to a statistical database should not allow an observer to learn anything new about an individual that they couldn't have learned without that database.

The Dalenius Principle

"If the release of a statistic $S$ makes it possible to determine the value of a characteristic $D_k$ of data subject $k$ more accurately than is possible without $S$, then a disclosure has taken place."

Think of this as comparing two worlds: In the Real World, the attacker has the statistics. In the Ideal World, they don't. If the attacker is noticeably more successful in the real world, privacy is lost. However, as intuitive as this sounds, it is mathematically impossible to achieve while still keeping the data useful. If we learn that "smoking causes cancer" from a dataset, we've learned something new about smokers in that data, even if it's a general trend.

5. The Modern Standard: Differential Privacy

Differential Privacy (DP) solves the Dalenius dilemma by changing the baseline. Instead of asking what an attacker knows "with vs. without" the dataset, we ask: What changes if one person's data is added or removed?

Definition 4.1: Neighboring Datasets

Let $D$ be a data domain. Two datasets $x, x' \in D^n$ are called neighboring if they differ on exactly one entry, i.e., $|\{i : x_i \neq x'_i\}| = 1$.

Definition 4.2: Differential Privacy

A mechanism $M : D^n \to R$ is $(\epsilon, \delta)$-differentially private if for all neighboring $x, x' \in D^n$ and for all events $S \subseteq R$,

$Pr[M(x) \in E] \leq e^\epsilon \cdot Pr[M(x') \in E] + \delta$

Key Properties of the Definition

  • The Parameter $\epsilon$: This is your "privacy budget." Smaller $\epsilon$ means better privacy. Usually, we aim for $\epsilon < 1$ (like 0.1 or 0.01). If $\epsilon$ is too small, the data becomes useless noise; if it's too large, privacy vanishes.
  • The Parameter $\delta$: This represents the probability of a complete privacy failure. We aim for $\delta$ to be extremely small—much smaller than $1/n$.
  • Randomness is Required: To satisfy this definition, an algorithm must be randomized. It must "blur" the results slightly so that the presence or absence of a single individual doesn't significantly change the output.
"Differential Privacy is a property of the algorithm itself, not the data. It provides a worst-case guarantee that protects everyone, regardless of what an attacker already knows."
